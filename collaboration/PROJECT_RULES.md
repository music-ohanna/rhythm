# 📜 Final-Rhythm 공통 운영 규칙 (Single Source of Truth)

이 문서는 Codex, 안티그래비티(Antigravity), 그리고 사용자 간 협업 시 모두가 반드시 준수해야 하는 **단일 원본 규칙 문서**입니다.

## 1. 역할 및 소유권
- **Codex**: 기획, 요구사항 명세(`SPEC.md`), 음악교육적 판단, 코드 감사(`AUDIT.md`), 최종 승인 요청
- **안티그래비티**: 실제 코딩, 반복 수정, 브라우저/반응형 테스트, 커밋 및 인수인계(`HANDOFF.md`)
- **사용자**: 디자인 및 교육적 선택, 규칙 변경 승인, GitHub 배포 승인

## 2. 10대 공통 운영 규칙
1. **작업 시작 전 필수 참조**: 작업을 시작하기 전에 `collaboration/PROJECT_RULES.md`, `collaboration/SPEC.md`, `collaboration/STATUS.md`를 반드시 읽고 현재 상태와 작업 범위를 파악한다.
2. **명세 범위 엄수**: 안티그래비티는 `SPEC.md`에 명시된 범위만 정확하게 구현하며, 임의로 범위를 확장하거나 변경하지 않는다.
3. **음악 도메인 규칙 보존**: 음악·박자(4/4, 6/8 등)·음가·V자 리듬 표기법 규칙을 임의로 변경하지 않는다.
4. **무분별한 정돈 금지**: 요청받지 않은 관련 없는 리팩터링, 스타일 재작성, 파일 위치 이동/정리를 하지 않는다.
5. **기존 사용자 작업 보존**: 기존 사용자가 작성하거나 수정한 코드를 덮어쓰거나 삭제하지 않는다.
6. **단위 커밋 지침**: 기능 하나당 가능한 한 하나의 명확한 Git 커밋으로 작성한다.
7. **다각도 검증 필수**: 변경 사항 발생 시 데스크톱, 스마트폰 반응형, 4/4, 6/8 박자, 오디오/리듬 재생 기능을 종합 검증한다.
8. **인수인계 기록**: 구현 완료 후 `collaboration/HANDOFF.md`에 변경 파일, 주요 함수, 테스트 결과, 미검증 사항, 커밋 해시를 빠짐없이 기록한다.
9. **배포 승인 필수**: `main` 브랜치 푸시와 GitHub Pages 배포는 사용자의 명시적 승인이 있을 때만 실행한다.
10. **감사 요청 전달**: 작업 완료 시 Codex가 검토할 수 있도록 감사 요청 프롬프트를 작성하여 사용자에게 제공한다.

## 3. 문서 소유권 정의
- `collaboration/PROJECT_RULES.md`: 공통 원본 (변경 시 사용자 승인 필요)
- `collaboration/SPEC.md`: Codex 전용 갱신
- `collaboration/HANDOFF.md`: 안티그래비티 전용 갱신
- `collaboration/AUDIT.md`: Codex 전용 갱신
- `collaboration/STATUS.md`: 현재 작업 담당자가 상태 전환 시 갱신
